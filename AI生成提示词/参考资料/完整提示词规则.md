# 完整提示词规则

所有视频模型完整使用本文件的基础指南、全参考指南、术语表和示例。共用写作要求见 `../SKILL.md`；镜头、参考职责、声音、时间线、文字与事实边界统一执行，字段、标签、章节和帧对齐句式按本次输出格式表达。结构化协议示例不改变自然语言或原样模式的输出契约。

## 使用顺序与当前运行约定

1. 按真实槽位识别文生、首帧、首尾帧、尾帧或多参考任务，不因题材、人物或音频词语擅自换模式。输出协议要求模式标识时，t2v 对应 T2VA；仅首帧对应 I2VA；首尾两帧对应 FL2VA；仅尾帧对应 L2VA；r2v、v2v、rv2v 对应 Ref2VA。
2. 基础任务使用下文《视频提示词写作指南》，参考任务使用下文《全参考模式》；术语固定译法见文末。结构化输出按本次字段清单使用三章节或六章节，保留规定的字段名、章节顺序、标签、关系标记和时间标记；自然语言输出表达同样完整的内容，不附加结构化标签和章节前缀。
3. 插件按请求 JSON 返回当前真实 segment_id 的最终结果。结构化格式返回章节对象，各值只含正文，由程序组装标题和实际首尾帧对齐句式；自然语言格式返回完整提示词字符串；原样格式保留原稿。独立使用时按用户指定格式交付。
4. 描述性正文中文，功能标识英文；对白、歌词、旁白及可见文字保持原语言和原标点。
5. 分镜、时间轴、声音身份、素材角色和切点已经定稿。下文设计建议仅帮助落实这些设计，不触发重新规划、新增剧情、重新分析素材或额外模型调用。原稿锁定的镜头数量、时长、主体数量和画风优先于默认建议；明确禁令优先于通用制作惯例。
6. 每段从零秒完整覆盖到实际结束，所有正式结果逐行使用给定秒级骨架；每个区间最长一秒，允许毫秒边界。切镜时刻是既定切点，不是每秒新增一个镜头。台词一次起说，后续节拍只描述持续发声与闭口。
7. 示例保留了参考职责、声音和镜头表达的完整上下文，示例素材及台词不是当前输入；部分示例为结构演示，未展开逐秒行，正式结果仍须写全当前时间线，不可照抄示例长度、时码、人物或音轨。
8. 参考内容仅据实际绑定、已保存素材理解与人物资料，不把文件名或未知音轨当作证据。当前流程不联网核查品牌，不上传或重新分析图像，不能把本文件的“验证”解释为调用工具或重新验收；无已验证事实就不编造。
9. 当前输出不写分辨率、像素尺寸或画幅比例；宽高比由执行参数保存。文中关于保持宽高比的要求是构图一致性，不能把它重新写成提示词参数。
10. 不设本地 tokens、字符或短篇字数目标。自查与局部表达修订在同一次生成内完成，不输出审查过程，不追加验收或修复请求。原样模式由主入口处理，不执行格式转换。

## 视频提示词写作指南（T2VA / I2VA / FL2VA / L2VA）

> 说明：最终提示词的字段名、标签、关系标记、任务类型前缀、说话人ID、对白标记、镜头标记、时间戳、帧对齐句式与运镜术语等指令性标识保持英文；各章节描述性正文用中文书写；对白、歌词、旁白与画面内可见文字保留其原始语言。文中示例代码块已按此规范呈现。

### 1. 任务概述

- **T2VA（文生视频）**：从文本构建完整的视听时间线。
- **I2VA（首帧图生视频）**：T2VA 主体 + 首帧指令 + 一条从首帧向前发展的视觉路径。
- **FL2VA（首末帧生视频）**：T2VA 主体 + 首末帧指令 + 一条从首帧到末帧的连续路径。
- **L2VA（末帧生视频）**：T2VA 主体 + 末帧指令 + 一条从合理前置状态收敛到末帧的路径。

### 2. 最终提示词结构

#### 2.1 第一部分是帧对齐指令

**T2VA** 没有图片对齐指令，直接以三个核心字段开头。

**I2VA** 固定使用：

```text
For the target video, at 0.00 seconds into the target video, <Picture 1> (from [Shot 1]) is fully referenced.
```

**FL2VA** 固定使用：

```text
How the reference pictures align with the target video — Picture 1 (from Shot 1) aligns with the 0.00-second mark of the target video; Picture 2 (from Shot N) aligns with the S.SS-second mark of the target video.
```

**L2VA** 固定使用：

```text
How the reference pictures align with the target video — <Picture 1> (from [Shot N]) aligns with the S.SS-second mark of the target video.
```

其中 `N` 是实际末镜头的编号，`S.SS` 是格式化为恰好两位小数的有效视频时长。该指令必须位于最终提示词的第一行，之后空一行再写核心字段。

#### 2.2 第二部分包含三个核心字段

```text
integrated_multimodal_description: [Shot 1] ...

overall_soundscape: ...

non_diegetic_music: ...
```

- **integrated_multimodal_description（综合多模态描述）**：沿时间线描述画面、动作、镜头、说话人、对白、演唱和画内音。
- **overall_soundscape（整体声景）**：概括整个视频中的环境音、物理动作声和非语言人声。
- **non_diegetic_music（非画内音乐）**：描述角色听不到、只有观众能听到的背景音乐。

### 3. 如何把关键帧融入多模态描述

#### 3.1 I2VA：从图片出发向前发展

`<Picture 1>` 是视频在 0.00 秒处的实际首帧，属于 `[Shot 1]`。描述应先确立图片中的风格、主体、构图和场景锚点，然后再描述接下来的动作。角色身份、服装、颜色、关键物体和空间关系应保持一致。

推荐结构：**首帧锚定 → 动作起始 → 持续发展 → 结果或反应**。

#### 3.2 FL2VA：描述首帧与末帧之间的路径

Picture 1 是开头，Picture 2 是结尾。重点描述主体如何移动、姿态如何变化、物体如何被操作、构图如何演变、场景或光线如何过渡。

FL2VA 一般倾向使用单镜头，以便模型从首帧到末帧连续插值。只有在明确指定时才使用多镜头。末帧必须由最后一个 `[Shot N]` 在视频结尾处到达。

推荐结构：**首帧状态 → 可观察的中间变化 → 差异逐步收窄 → 末帧状态**。

#### 3.3 L2VA：推断开头并在结尾落在图片上

`<Picture 1>` 是视频的末帧，属于最后一个 `[Shot N]`；它天然不属于 Shot 1。独立创作且获得授权时可根据用户意图和末帧推断合理的更早状态；插件内起始状态、动作和切镜已经定稿，沿用这些依据，描述角色、物体、运镜和场景如何逐步接近参考图片，不另写新剧情。

推荐结构：**合理的前置状态 → 明确的动作与过渡路径 → 末镜头逐步收敛 → 末帧落定**。

### 4. 如何书写三个共用核心章节

#### 4.1 沿时间线展开多模态描述

`integrated_multimodal_description` 是改写提示词的主体。每个细节都应对应可见或可听的内容：视觉风格、初始构图、主体外观与位置、场景与关键道具、动作与反应、镜头变化、说话语言，以及同步的画内音。

在 `[Shot 1]` 开头，说明整体风格和初始构图。常见风格包括「电影感」、「实拍」、「2D 动画」、「3D CG」、「黏土定格」、「水彩」和「复古胶片」。关键帧任务从参考图片推导风格；T2VA 从用户文本中选取风格。

```text
[Shot 1] 实拍、电影感，一个中全景框住……
```

#### 4.2 镜头与切镜

第一个镜头不加时间戳。后续镜头使用顺序编号，并以严格递增、且位于视频时长内的切镜时间点开头：

```text
[Shot 2] At 00:03.500，镜头切到……
```

普通切镜使用「镜头切到」、「画面切到」、「镜头转到」、「镜头换到」或「镜头切换到」。当用户明确要求时，也可以使用叠化 (cross-dissolve)、淡入淡出 (fade) 或划像 (wipe)。切镜应引入关于主体、空间、状态、视角或时间的新信息。如果只需要改变景别或轻微角度，优先使用运镜。

#### 4.3 运镜：运动类型 + 幅度 + 速度

完整的运镜表达有三个维度：**运动类型**定义摄影机如何移动，**幅度**定义构图变化的范围，**速度**定义变化的节奏。只在有意义时添加幅度和速度；中等幅度和正常速度通常省略。

| 维度 | 可用表达 | 说明 |
|-|-|-|
| 运动类型 | `Zoom In / Zoom Out` | 机位不动，焦距变化（变焦推近/拉远） |
| 运动类型 | `Push In / Pull Out` | 摄影机向前/向后移动（推/拉镜头） |
| 运动类型 | `Pan Left / Pan Right` | 机位不动，镜头水平转动（左/右摇） |
| 运动类型 | `Truck Left / Truck Right` | 摄影机水平平移（左/右横移） |
| 运动类型 | `Tilt Up / Tilt Down` | 机位不动，镜头垂直转动（上/下摇） |
| 运动类型 | `Pedestal Up / Pedestal Down` | 整个摄影机向上/向下移动（升/降镜头） |
| 运动类型 | `Arc Shot` | 摄影机绕主体做弧形运动（环绕镜头） |
| 运动类型 | `Tracking Shot` | 摄影机跟随移动的主体（跟拍镜头） |
| 运动类型 | `Static Shot` | 机位与镜头保持静止（固定镜头） |
| 运动类型 | `Shake Slightly / Shake Strongly` | 轻微/强烈晃动 |
| 运动类型 | `POV` | 主体的主观视角 |
| 运动类型 | `Roll Clockwise / Roll Counterclockwise` | 摄影机绕镜头轴顺时针/逆时针滚转 |
| 幅度 | `with small amplitude` | 小范围变化 |
| 幅度 | `with large amplitude` | 大范围变化 |
| 速度 | `at slow speed` | 慢速运动 |
| 速度 | `at fast speed` | 快速运动 |

运镜应写成镜头内自然的中文动作描述，而不是堆叠在句尾的孤立标签：

```text
镜头以小幅、慢速向她手中折叠的信推近 (Push In)。
镜头以大幅、快速右摇 (Pan Right)，展现敞开的门口。
镜头保持固定 (Static Shot)，跑步者走出画面。
```

#### 4.4 说话人、对白与演唱

说话、演唱或发出画外人声的主体使用稳定的 ID，如 `(S1)` 和 `(S2)`。当多个已编号的说话人一起说话或演唱时，使用复合 ID，如 `(S1,S2)`。说话人跨镜头保持同一 ID；从不发声的角色不分配说话人 ID。

说话人首次出现时，从视觉和声音上下文提供足够信息以确立稳定身份，例如角色类型、年龄、性别、是否在画面内、音高、音色、语速或口音。说话人的识别短语、ID、动作和表达方式放在 `<d>` 之外；`<d>` 内只放语言标签和用户提供的实际说话内容。逐字逐标点保留原文；不要翻译或改写。

```text
安静、气息感嗓音的年轻女性 (S1) 说：<d>[English] I get off at the next station.</d>
两个孩子 (S1,S2) 一起喊道，<d>[English] Wait for us!</d>
```

画外音用中文短语「以画外音说道」表达。每个画外音 `<d>` 块之后，立即说明对应画面内角色的嘴唇保持闭合：

```text
男性 (S1) 以画外音说道：<d>[English] I still remember that road.</d>，同时他的嘴唇完全闭合。
```

当同一句对白或歌词跨越切镜时，在两部分的衔接处使用 `<scenetrans>`，并明确说明声音跨切镜延续。当语音被视频结尾截断时使用 `<cutoff>`。连续性可以用「无缝延续到切镜后」、「不中断地延续到下一镜头」、「从上一镜头延续过来」或「在转场中仍可听到」来表达。

#### 4.5 画面内文字

任何实际出现在画面上的横幅、招牌、标签、字幕或霓虹灯文字，都放在英文双引号内。逐字保留原文和标点，不做翻译。

```text
一块红色霓虹灯招牌写着 "营业中" 在门口上方发光。
```

#### 4.6 overall_soundscape（整体声景）

用 1–4 句中文，在一个连续段落中概括整个视频的环境音、物理动作声和非语言人声，例如风声、雨声、交通声、脚步声、衣物摩擦声、撞击声、呼吸声、笑声或喘息声。对白、演唱和画内音乐已属于多模态描述，不要在此重复。没有要求或没有依据支持环境音/物理声，或明确要求静音时使用 `N/A`，不能为了填满声音字段发明声源。

```text
overall_soundscape: 持续的雨点轻敲咖啡馆窗户，下方是低沉的房间环境音。入口门铃响一次，随后是湿漉漉的脚步声和椅子轻微的摩擦声。
```

#### 4.7 non_diegetic_music（非画内音乐）

用 1–3 句中文描述角色听不到、只有观众能听到的背景音乐。聚焦配器、速度、节奏和动态变化；不要使用抽象情绪词，也不要解释配乐的情感功能。角色能听到的演唱、乐器、广播、电视或手机音乐属于画内事件，应出现在多模态描述中。没有非画内音乐时使用 `N/A`。

```text
non_diegetic_music: 慢速的稀疏钢琴音符，加入持续的低音弦乐，音量逐渐增强后淡出。
```

### 5. 示例

#### 示例 1：T2VA

没有参考图片时，直接从文本构建完整时间线。独立创作且获得明确扩写授权时可以补充与用户意图一致的细节；插件当前已定稿分镜只细化原有动作过程，不新增场景、角色、台词、声音或运镜。

```text
integrated_multimodal_description: [Shot 1] 实拍、电影感，一个中全景框住一位面包师在日出前打开小街边面包店的百叶窗。镜头以小幅、慢速推近 (Push In)，中年面包师用平静、略带沙哑的嗓音 (S1) 把一条新鲜面包放到木质柜台上，说道：<d>[English] First batch of the morning.</d> [Shot 2] At 00:05.000，镜头切到切开的面包上升起的蒸汽特写，同时面包师最后的话语从上一镜头延续过来。

overall_soundscape: 木质百叶窗在安静的街道上刮擦着打开，店内托盘轻轻碰撞。门铃响一次，随后是轻快的脚步声和切面包的清脆声响。

non_diegetic_music: 中速柔和的原声吉他旋律，加入稀疏的低音提琴音符，结尾轻柔淡出。
```

#### 示例 2：I2VA

先写首帧指令，然后把 Picture 1 中的主体、构图和场景作为 Shot 1 的起点，再描述场景如何继续发展。

```text
For the target video, at 0.00 seconds into the target video, <Picture 1> (from [Shot 1]) is fully referenced.

integrated_multimodal_description: [Shot 1] 实拍、电影感，<Picture 1> 中显示的年轻女性仍在雨水覆盖的火车窗边，保留她的外观、服装、座位位置和车厢布局。镜头以小幅、慢速右横移 (Truck Right)，她把目光从折叠的信件抬向窗外掠过的城市灯光。她的倒影在玻璃上移动，同时安静、气息感嗓音的年轻女性 (S1) 说：<d>[English] I get off at the next station.</d> 她沿已有的折痕把信折好。

overall_soundscape: 火车轮子在低沉的通风嗡鸣下产生稳定的金属节奏。雨点轻敲窗户，纸张在她手中轻轻沙沙作响。

non_diegetic_music: 慢速持续的大提琴音符，配以间隔宽远的钢琴音，音量逐渐减弱。
```

#### 示例 3：FL2VA

两张图片分别锚定开头与结尾。主体部分不应重复两段静态图片描述，而应提供连接二者的运动路径。以下示例是一个 8 秒单镜头。

```text
How the reference pictures align with the target video — Picture 1 (from Shot 1) aligns with the 0.00-second mark of the target video; Picture 2 (from Shot 1) aligns with the 8.00-second mark of the target video.

integrated_multimodal_description: [Shot 1] 实拍、电影感，一位淋湿的骑行者从 Picture 1 确立的位置和取景开始，在银色自行车旁拿着一把合起的黑伞。镜头以小幅、慢速拉远 (Pull Out)，她松开自行车把，把伞举过肩膀，向上推动伞骨直到伞面打开。水从展开的伞布上滚落，同时她走到伞下，把伞柄转到最终角度，并在镜头结尾落入 Picture 2 确立的姿势、间距和构图。

overall_soundscape: 雨稳定地落在路面上，随后是伞骨的金属咔嗒声和伞面打开的轻响。水从自行车架滴落，远处交通驶过。

non_diegetic_music: N/A
```

#### 示例 4：L2VA

图片只锚定最后一个瞬间。先确立一个兼容的更早状态，然后让动作、物体状态和构图在最后一个镜头中逐步落到 Picture 1 上。以下示例是一个 6 秒单镜头。

```text
How the reference pictures align with the target video — <Picture 1> (from [Shot 1]) aligns with the 6.00-second mark of the target video.
```

## 全参考模式（Ref2VA）精炼版

> 任务类型、参考标签与保留标记的固定译法见本文末尾合并的《翻译规范与术语表》。

### 0. 角色与绝对输出契约

您是 MiniMax H3 R2VA / Ref2VA / 全参考视频提示词工程专家。当任务包含任何复杂参考关系时使用本规范：多参考图像、可复用的角色或产品身份、场景/风格迁移、源视频编辑或续写、音频复用/参考、数字人表演、唱歌/口型同步、MV 生成、品牌/产品资产、字体参考、分镜参考，或任何需要明确保留分析的场景。

- 独立文本交付只输出最终六节提示词，不输出问候、解释、代码块、道歉、注释、清单或对话填充语；直接以 `subject_definitions:` 开头，以 `non_diegetic_music:` 的内容结束。插件内按本次请求输出包含真实 segment_id 和六个章节正文的 JSON 对象，由程序组装章节标题，不用六节纯文本替代 JSON。
- 六节固定顺序：`subject_definitions:` → `summary:` → `retention_analysis:` → `detailed_description:` → `overall_soundscape:` → `non_diegetic_music:`
- 六个章节的字段名、参考标签、关系标记、任务类型前缀、说话人ID、对白标记、镜头标记、时间戳、帧对齐句式与运镜术语等指令性标识保持英文；各章节的描述性正文用中文书写。对白、歌词、旁白与画面内可见文字保留其原始语言。
- `detailed_description` 必须详细、明确：对每个镜头清楚确立当前构图、主体外观与位置、环境与光线、动作与状态变化、运镜、当前声音，以及参考内容实际出现或生效的时间点。不得把描述简化成剧情概述或参考关系列表。

### 1. 参考标签系统（`subject_definitions`）

| 标签 | 含义 |
| --- | --- |
| `<Subject N>` | 从参考素材中抽象出的可见内容，可在目标视频中复用或修改 |
| `<Picture N>` | 用作具体首帧、关键帧、末帧、剪辑关键帧或构图/分镜锚点的参考图片 |
| `<Video N>` | 提供剪辑源、续写起点或整片时间/镜头/剪辑结构的参考视频 |
| `<Audio N>` | 被复制或引用的独立音频素材，或参考视频中启用的同步音轨 |

编号与顺序：
- 精确保留用户原始素材顺序，按用户顺序分别映射 `<Picture N>`、`<Video N>`、`<Audio N>`；三类编号互相独立，只表示类内顺序（同一参考视频可对应 `<Video 1>` 与 `<Audio 2>`）。不按感知重要性重排：即使 Picture 2 是更强的角色参考，它仍是 `<Picture 2>`。
- 标签一经分配，在全部章节中保持同一含义。

定义规则：
- 每个需要单独追踪的内容单元各占一行，说明其标签所指、参考角色和需遵循的主要特征，必要时注明源素材。若 `<Picture N>` / `<Video N>` 只用于标识另一个被参考项的来源、之后不被单独分析，则直接在该项定义中引用，不单独成行。
- `<Subject N>` 是可复用内容单元（人/动物/物体、场景/背景/环境、服装/道具/界面/视觉效果、风格/动作/表情/姿态），不是源文件本身；一个主体可由多个素材定义，一个素材也可提供多个主体。来自多个素材时合并来源并说明各素材提供什么。
- `<Picture N>` 仅当图片本身作为帧锚点、分镜或构图参考时独立成行；若图片仅定义角色、场景、服装或风格，在对应 `<Subject N>` 定义中引用图片来源。图片作分镜/镜头规划参考时，说明它映射到哪些镜头、提供了什么（视点、主体位置、镜头顺序）。
- `<Video N>` 只用于整片层面关系（剪辑源、续写起点、整片运镜/切镜/节奏/时间结构参考）；视频中的可见人物/物体/场景仍归 `<Subject N>`，`<Video N>` 不替代主体标签。
- 普通参考视频不会因文件带声音就自动产生 `<Audio N>`；仅当该音频被复制、保留、作为启用的同步音轨，或被明确引用（音色、词语、节奏、音乐、环境音、声音质感、节拍、连续性）时才定义。`<Audio N>` 的定义说明音频角色即可，不必指明来自哪个 `<Video N>`，仅在需要消除来源歧义时说明共同来源。一个音频素材承担多个角色时用一句自然语言描述，不创建子章节。
- `<Audio N>` 明确对应目标说话人时，在定义中复用其全局 ID：`<Audio 1> 是 <Subject 1> (S1) 的音色参考。`（Sx）来自目标视频全局说话人顺序，绝不在音频定义中独立分配或重新编号。
- 主体从真实人物参考被风格化时，说明其保留可识别身份锚点、渲染遵循所请求的目标风格。较新的批准资产（用户修改/重新生成/替换/明确批准）取代旧资产后，一切后续定义与描述以最新版本为唯一权威，除用户要求组合版本外不混用新旧细节。

示例：

```text
<Subject 1> 是 <Picture 1> 中的年轻女性，留深色长发，穿蓝色开衫，戴一条细银项链。
<Subject 1> 是这位女性，其外观来自 <Picture 1>，行走动作来自 <Video 1>。
<Picture 2> 是 [Shot 1] 的首帧，画面为一位女性坐在咖啡馆窗边。
<Picture 3> 是 [Shot 1] 和 [Shot 2] 的分镜参考，定义它们的视点、主体位置与镜头顺序。
<Video 1> 是目标视频剪辑的源视频。
<Audio 2> 是 <Video 1> 的同步音轨，并在目标视频中被复用。
```

### 2. `summary`

用一个简短中文段落概括目标视频及参考关系，以方括号任务类型前缀开头。

| 任务类型 | 使用时机 |
| --- | --- |
| `keyframe completion` | 图片作为目标视频的首帧、关键帧、末帧、剪辑关键帧或其他具体帧锚点 |
| `reference generation` | 图片、视频或音频为角色、场景、风格、动作、运镜、分镜、节奏等提供生成引导，但不作为具体帧，也不是被剪辑/续写的源视频 |
| `video editing` | 直接修改已有源视频；剪辑图片或在静态关键帧之间生成不属于此类 |
| `video continuation` | 新内容从已有源视频继续、延伸、接续或过渡 |
| `audio reuse` | 同一音频信号被完整或部分复用 |
| `audio reference` | 不复制音频信号，仅参考其音乐风格、音色、对白或歌词内容、音效质感、节拍或连续性 |

- 满足多个关系时用 ` + ` 组合且不重复类型，如 `[video continuation + keyframe completion]`、`[video editing + audio reuse]`。
- 视频或音频的单纯存在不会自动产生任务类型：参考视频只提供运镜/切镜/节奏时属 `reference generation`，仅当被直接剪辑或续写才用 `video editing` / `video continuation`。剪辑源视频且其原声仍可听时同时加 `audio reuse`；续写但不复制信号、新音频只是延续原轨可听特征时用 `audio reference`。
- 只使用 `subject_definitions` 已定义的标签，不在本章节引入新标签。
- 视频剪辑任务在前缀后以 `目标视频是 <Video 1> 的剪辑版本。` 开头。
- 数字人或 MV 任务须说明可见表演者正在对着相关 `<Audio N>` 或锁定的 `<d>` 内容演唱、说话或口型同步。

### 3. `retention_analysis`

每个已定义的参考标签一行，保持 `subject_definitions` 中确立的含义，记录出现位置与保留方式：

```text
<Subject 1>（出现在 [Shot 1]、[Shot 3]）: fully_preserved - ……
<Picture 2>（[Shot 1] 首帧）: fully_preserved - ……
<Video 1>（剪辑与节奏结构）: weak_reference - ……
<Audio 1>: fully_copy - <Audio 1> 以 1:1 完整复用为目标视频的最终完整音轨。
<Audio 2>: reference - 目标说话人遵循 <Audio 2> 的音色与沉稳语调，但不复制原始信号。
```

可见内容（`<Subject N>` / `<Picture N>` / `<Video N>`）关系标记：

| 关系标记 | 含义 |
| --- | --- |
| `fully_preserved` | 被参考内容的定义角色被完全保留 |
| `partially_preserved` | 仍被使用，但部分定义特征被改变或仅部分保留 |
| `attribute_transfer` | 被参考的特征迁移到另一个可识别的目标主体 |
| `weak_reference` | 仅保留风格、类别、构图、节奏或氛围上的宽泛相似 |

音频（`<Audio N>`）关系标记：

| 关系标记 | 含义 |
| --- | --- |
| `fully_copy` | 完整源音频作为目标视频的完整最终音轨 |
| `partially_copy` | 仅复制部分时间线或选定音频层，或复制后增删替换了其他声音 |
| `reference` | 不直接复制信号；仅参考音色、节奏、音乐风格、对白内容、情感、节拍或声音质感 |
| `weak_reference` | 仅保留类别或氛围上的宽泛相似 |

- 关系标记只能在 `subject_definitions` 中为该标签已定义的参考角色范围内选择。
- 不要把目标视频中新增的动作、背景、剧情事件或必要的口型同步表演当作参考保真度损失，除非它们与已定义的参考角色矛盾。
- 本章节绝不写 `(Sx)` 说话人 ID。
- 主体说话但保留参考特征时示例：`fully_preserved - 人物的面部身份、发型、服装和配饰被保留，同时人物执行新的口型同步演唱。`

### 4. `detailed_description`（主体章节）

按目标视频播放顺序逐镜头描述画面、动作、声音、声音表演与参考使用，在适用处插入参考标签。

开头风格：
- 在 `[Shot 1]` 之前用一两句中文确立目标视频的风格、格式、光照/色彩语言与音频表演方式，仅依据用户输入、参考或授权扩写支持的内容；纯转换模式未指定风格时用中性措辞，不发明特定流派、情绪或光照方案。
- 多镜头输出时该开头是全局美学头部：色彩分级、材质语言、纹理/颗粒行为、光照方向、镜头语法与动态词汇在各镜头间保持一致，除非有意的节拍改变它们。
- 用户指定的宽高比、时长、活动语言、产品变体与品牌约束须贯穿全章节，不让单个镜头暗示不同目标。

镜头基础格式：
- `[Shot 1]` 标记开场镜头、不带时间戳；后续镜头用 `[Shot N] At MM:SS.mmm, ...` 标记切镜时间；时间戳必须递增。
- 运镜写成当前镜头内自然的中文描述（运动类型、幅度、速度、轴线）；镜头静止时说明锁定；不引入用户未请求、参考关系不需要的运镜。
- 给实际发声来源按目标视频中发声事件顺序一次性分配稳定的 `(S1)`、`(S2)` 及后续 ID，并在每个发声事件处复用。对白和歌词写作 `<d>[Language] ...</d>`。
- 同一主体画外说话时保持 `<Subject N> (Sx)` 形式并明确标记 off-screen；说话人不对应任何已定义主体时用稳定声音描述 + `(Sx)`。
- 语言内容只是直接复用的 BGM/完整配乐中的提示、且无任何独立发声来源实际发出时，用 `<Audio N>` 作可听来源，不虚构 `(Sx)`；由具体的人/角色/旁白实际发出才分配 `(Sx)`。
- 对白跨切镜用 `<scenetrans>`；语音被视频结尾截断用 `<cutoff>`；跨镜头连续声音写对应的连续性描述。
- 对白、歌词、旁白与画面内文字保留原始语言，不翻译、总结、释义、重排或截断；难以听清的片段写 `[unclear]`，不猜测转述；用户锁定的台词、歌词和可见文字逐字逐标点保留，不为格式改写标点或删去原文符号。仅整理未锁定的独立创作文本时，标点可规范为 `,` `.` `?` `!`，去除无意义的装饰符号，并按语气以 `.` `?` `!` 结尾。仅参考音色/节奏/情绪/表达时，不把参考音频的原对白带入目标视频。

参考标签在镜头中：
- 重要 `<Subject N>` 首次清晰出现时描述其被参考特征、画面位置与当前动作（限定在镜头实际可见内容），后续镜头继续用同一标签、不重复定义。
- 具体帧锚点用自然措辞：`镜头从 <Picture 1> 开始` / `镜头的关键帧对应 <Picture 2>` / `镜头结束于 <Picture 3>`。
- 在源状态、剪辑、续写、运镜、节奏或时间结构生效处引用 `<Video N>`；在复制或参考角色活跃的镜头/语义阶段引用 `<Audio N>` 并说明信号是被复制还是被参考。

每个镜头在素材支持时应包括：镜头尺寸或构图；前/中/背景关系（空间清晰度重要时）；主体画面位置与朝向；同一场景多镜头时固定地标及其屏幕相对位置；光照基线（主/补/轮廓光方向或继承光源）；当前身份/参考锚点；环境、光照与色彩情绪；一个主要动作或信息节拍；身体/面部/物体/场景/排版/UI 的可见状态变化；运镜、速度、幅度与轴线；与该镜头相关的声音、发声事件、环境音或有意静音；多镜头时从上一镜头的连续性交接与对下一镜头的设置；先前可见的重要主体离开画面时的退场状态（从何处退出、假定在何处、为何不再可见，至少在下一个相关镜头中跟踪）。

镜头数量与时序设计：
- 5 秒或更短通常 1 个镜头；10-15 秒纯转换用 1 个镜头或源素材所需最少数量、扩写授权或复杂参考任务可 1-4 个；30 秒以上仅当时长、源序列、音频时间线或授权扩写要求时做多镜头分解。纯转换模式不为了视觉多样性拆分镜头。
- 独立创作且未给定镜头结构时，单个镜头通常按不超过 15 秒规划，较长节拍可拆成短镜头；已有分镜、一镜到底和接入模型的真实执行能力优先。插件不能据此拆段、增切镜或把 15 秒当作本地硬上限。
- 同一镜头中有重要动作或对话的主体通常不超过 3 个，除非用户要求人群、集体或团体表演。
- 剪辑必须引入视点、动作、信息、表演强度、时间或构图的有意义变化；仅距离变化时优先受控的推近/拉远/焦距变化而非剪辑。
- 节奏有高峰与制动：更快的运动、剪辑、冲击与能量只用在有深远意义的揭示、节拍击打、交互触发或证明时刻；面部、口型同步、关键产品、标志、UI、可读文本与最终结束画面保持稳定或减慢。
- 叙事性多镜头视频（用户请求或扩写授权时）在时间线上分布信息钩子（揭示、反转、呼应、悬念、温情节拍、追逐、高潮、表情节拍），开头和结尾镜头各有明确目的。
- 复杂动作、复杂场面调度、长单镜头、多角色、MV 节拍映射、产品演示、UI 交互或脆弱连续性，用自然散文的每秒/亚秒指令覆盖（`从 00:00 到 00:01，……`），每条指令涵盖动作/姿势/表情、镜头、空间位置、音频提示与到下一时刻的交接。

描述长度：
- 所有生成任务按真实时长与源信息复杂度充分展开完整秒级时间线；取消旧的 350-500 字目标，不设本地 tokens 或字符上限，输出长度由接入模型能力决定。不得为凑字数发明场景、动作、运镜、音乐、排版、声明或情绪细节。对白密集内容优先覆盖完整说话时间线；视频剪辑任务篇幅随源视频复杂度伸缩；单镜头不自动构成缩短描述的理由。每次生成都必须逐行覆盖本段 00:00.000 至实际结束，每个区间不超过一秒，允许毫秒边界和非整数段尾；每句锁定台词只在起说节拍出现一次。

### 5. `overall_soundscape` 与 `non_diegetic_music`

- `overall_soundscape`（1-4 句中文）概括整片环境音与物理声：房间音调、环境氛围、拟音、呼吸、脚步声、布料摩擦、产品敲击、UI 点击、材质声、复制的环境音层等。对白、演唱以及与特定镜头同步的声音事件留在 `detailed_description`，完整对话和歌词绝不在本章节重复；不描述仅供观众收听的配乐；仅当无环境音/物理声或静音系有意/被请求时写 `N/A`。
- `non_diegetic_music`（1-3 句中文）描述角色听不到、仅观众能听到的背景音乐；存在时说明配器、速度、能量、动态发展及与 `<Audio N>` 的关系；没有时写 `N/A`。
- 使用参考音频时，其复制或参考关系只写在与其可听层匹配的章节：环境音与音效 → `overall_soundscape`，仅观众可听的配乐 → `non_diegetic_music`；同一音频同时提供两类内容时在两章分别描述对应关系。
- 不创建重复音乐层：`<Audio 1>` 已被复用为最终歌曲/配乐时，不再发明无关 BGM。上传歌曲若是 MV 主音频或数字人表演音轨，在 `detailed_description` 中描述其积极使用，不降级为通用背景音乐。
- 存在旁白/对话且 BGM 被请求、提供或已暗示时，说明 BGM 支撑并保持在语音之下，不与语言信息竞争；叙事/3D/品牌短片的配乐是一个连续的情感层，跨镜头保持，除非用户要求分段音乐。

### 6. 执行纪律：重写 vs 扩写与保真锁定

- 默认严格转换：仅把给定内容、参考、音频角色、约束和时序组织进六节，不发明新情节点、角色、产品、品牌、主张、场景、镜头运动、音乐、对话、歌词、可见文本或不相关动作。

- 扩写也仅扩到视频可播放、连贯、技术上可提示的程度；添加的细节必须支持用户声明的意图，不得与用户提供的任何主题、动作、场景、镜头指令、音频角色、歌词、对话、可见文本、时长、宽高比、风格或禁令相矛盾、替代、削弱、重新排序、翻译、重新风格化或静默修改。

- 输入不够具体且未触发扩写时：保持中立简洁、省略不支持的细节、用保留源材料所需的最小镜头结构，不用发明的故事、氛围、镜头编排、音乐或视觉填充空白。

### 7. 数字人 / 说话头像 / 口型同步 / MV 模式

激活条件（满足任一项即触发）：用户明确要求数字人、说话头像、虚拟人、发言人、可见口头叙述、口型同步、嘴部同步、"数字人""口播""对口型""说话""唱歌""MV""根据音频内容唱歌"、对着镜头唱歌或说话的人物；或用户同时提供一个人物肖像/参考人物与对应该人物的旁白、人声音频、歌曲、歌词、脚本或口语文案；或要求该人物表演该音频。非该角色的音频、背景音乐、环境音或音效不因与肖像同时存在而触发。用户明确仅要求画外音时，按画外音规则处理。

表演规则：
- 可见表演者必须定义为 `<Subject N>` 并在第一个实际发声事件处获得稳定说话人 ID `(Sx)`；单一主要数字人默认 `<Subject 1> (S1)`。
- 用户提供的歌曲/语音/人声音频若要求该人物表演，定义为该主体的表演、口型同步、语音或歌曲音轨 `<Audio N>`；可见人物本应表演时，绝不把该音轨仅仅描述为背景音乐。
- 每个唱歌/说话/说唱/口型同步镜头都明确描述同步嘴型、下颌运动、呼吸时机、面部强调与表演节奏；发声秒数内描述张嘴/闭嘴行为。
- 以面部为中心的数字人请求保持动作克制：小幅头部移动、自然眨眼、受控表情、呼吸与口部活动；除非被请求，不加舞蹈、行走、手势编排、戏剧性情节或分散注意力的切换镜头。
- 说"数字人"但没有脚本或音频时：推断为可见说话头像任务但不发出明确词语（除非用户要求生成文案）；无可用词语时描述准备发声的静默表演，或说明人物自然等待、无音乐内容。
- 用户只要画外音时：屏幕人物不做口型同步，说明其嘴唇保持闭合或仅自然呼吸。

歌词与锁定文本：
- 用户提供的歌词/对话/旁白/脚本是锁定的源文本，是唯一可被说出、演唱、显示或用于歌词排版的言语内容（除非用户明确要求重写）。
- 要求做 MV 或数字人歌曲但未提供歌词时，不生成歌词；明确要求原创歌词时才创作适合目标时长的完整简洁歌词，放入 `<d>[语言] ...</d>`。
- 书面文本与参考音频冲突时，书面文本是最终对白/歌词，音频仅作音色、节奏、韵律、情感或节拍参考（除非用户明确要求直接复用音频）。

MV 主音频与剪辑：
- 除非用户说要替换，上传的歌曲或人声音频是主表演源，同一主音频源在所有相关镜头保持连续；源音频长于目标视频时锁定一个音乐窗口（优先用户时间戳，否则在独立创作且有真实音轨分析时选择能支撑所请求表演的连续窗口；插件仅沿用已定窗口，不知道音轨时码时不猜测精确窗口），不在不同音频时刻之间静默跳跃。
- 长于单个模型片段的视频拆为连接镜头并维持一个全局主音频时间线；剪辑点落在乐句停顿、呼吸、军鼓击打、贝斯下降、重拍、声乐重音或有意的视觉冲击上；避免在开口元音、说唱音节或可见嘴型中间硬剪，除非下一镜头明确以特写继续同一嘴型和声乐短语。
- 可见表演者通过嘴型、下颌开合、吸气、眼神强度、头部节奏、肩部/手部重音与情感强调匹配声乐分句。观众收听的配乐归 `non_diegetic_music`，表演歌曲与声乐归 `detailed_description`；完整音频被复用为最终配乐时在 `retention_analysis` 标记 `fully_copy` / `partially_copy` 并在对应音频章节描述。
- MV 中歌曲窗口、当前演唱的歌词行、嘴部/呼吸时机、手势重音与节拍击打都写进镜头描述；口述/唱/说唱的声乐行使用 `<scenetrans>`（跨剪辑）与 `<cutoff>`（结尾截断）。

### 13. 专门设计触发器

仅当用户请求、参考资产或目标格式明确触发相应类别时才应用；专门规则约束触发内容的写法，不授予扩写权限。纯转换模式下不添加叙事主线、歌词排版事件、产品证明链、UI 状态、应用流程、3D 故事结构、纸艺机制、额外镜头切换、配乐层或活动文案。

UI / 游戏 / 交互屏幕（UI、应用、仪表板、网站、游戏菜单提示词）：
- 保留参考框架、布局、信息层级、导航逻辑、交互逻辑与状态含义；风格迁移可改变材质处理、调色板、排版纹理、图标语言、装饰图案与氛围，但不得打乱功能阅读顺序或核心控件含义。
- 清晰阅读路径：标题/状态 → 主要主题或交互区域 → 主要操作/状态/核心文本 → 次要信息；主要按钮、选定状态、READY/LOADING、进度条或关键证明结果是视觉目的地，不被埋在装饰元素中。
- UI 围绕重要主题、产品证明、角色面部、嘴巴与交互区域而不遮挡；菜单、HUD、叠加层、卡片、标签在主要主题周围留稳定安全空间。
- 交互状态（悬停、按下/点击、选定、禁用、READY、LOADING、进度、成功、错误、非活动）用一致的视觉语言贯穿镜头：共享颜色、亮度、边框、填充、运动与时序规则；不为填满画面发明虚假状态或重复标签。
- 带角色的游戏菜单：每个角色绑定稳定侧面、玩家卡片、姓名/昵称、服装/身份锚点、颜色强调与可读状态；玩家卡片用清晰三级层次（玩家标签、昵称/姓名、READY 或等效状态），统一图标，无换行或重复文本；Continue/Start/Settings/Exit 风格菜单项保持单行、尺寸一致。
- 菜单与 HUD 排版按参考布局要求保持单行；可读性失败时先减少文案、按钮数量、图标或装饰元素。
- 游戏菜单与宣传 UI 构图可在需要设计感促销界面时用 Z 形阅读路径：玩家/状态区域 → 角色或主要视觉证明 → 菜单堆栈 → 主要行动号召；主要行动号召（Continue、Start 或选定操作）保持最强视觉焦点。
- UI/游戏颜色系统约五种有目的的颜色内：主背景、UI 主体、文本、功能强调色、警告/危险色；角色、UI 面板、按钮、图标与状态标签共享同一系统，用接触阴影、轮廓光、环境反射或柔和遮挡让角色与 UI 融入同一场景。

产品广告：
- 多个产品参考图/锚点图视为身份、材质、构图、光照与排版/风格约束，不是自动的字面镜头顺序、轮播、网格或产品墙；仅当用户要求或产品比较确需时使用轮播/网格/阵容编排。
- 文案动画（被请求可见文案时）：文本是构图证明区域附近的集成设计元素，不放字幕位；两部分运动：短句一先进入 → 短句二随后进入 → 短句一略微移动腾出空间，全程保持一行可读。
- 文案颜色随场景逻辑：白色/明亮极简空间中第一部分黑/深灰、第二部分/强调用实际产品主色；黑色/深色轮廓光空间第一部分可白、强调仍用产品主色。
- 极简产品电影（仅当用户请求产品电影提示词或授权扩写）：镜头设计从产品实际类别、形状、材质、结构与可能的可见动作推导（边缘、高光、开口、铰链、旋转、磁力接触、屏幕变化、喷雾、折叠、卡扣、滑动、颜色排列）；纯转换模式不引入这些运动。节奏交替吸引与制动：以即时有趣的产品角度或动作开场 → 材质/细节保持可读性 → 高峰放在真实产品动作或文案揭示 → 稳定的全幅产品+文案定格结束；避免空洞白色等待、廉价镜面地板、通用粒子、虚假 HUD 和所有镜头相同的缓动。

品牌 / 促销 / 服务 / 活动：
- 仅当用户请求该结构、授权扩写或参考已提供状态时，使用 2-5 种有意义的颜色/光照/材质状态（与过程、功能、结果、情感或品牌过渡相关）；避免随机颜色循环、任意渐变和每节拍相同缓动。
- 仅当用户请求品牌/服务电影或授权扩写时遵循证明链（用户情境 → 交互/过程 → 能力 → 输出/证据 → 价值/结果 → 标志 → 行动号召）；纯转换模式不发明这些节拍，不用通用蒙太奇。
- 品牌语言遵循资产、受众与平台；除非用户要求或活动上下文明确需要，不翻译或本地化品牌文案、UI 文案、标语、行动号召或可见文本。

3D / 角色动画 / 玩具电影 / 黏土 / 吉祥物 / 风格化表演：
- 角色运动重要时包含可读的动画表演原则：动作前预备、动作后惯性跟随、清晰剪影、强动作线、富有表现力的眼睛、微表情、仅在媒介支持处受控挤压与拉伸；避免僵硬解剖、无生气表情、未请求的塑料玩具皮肤和失去角色吸引力。
- 风格化 3D 角色保留身份锚点并用连贯的风格化比例系统：简化几何形式、可读身体块、清晰头发形状、适当时温暖次表面皮肤，以及富有表现力的眉毛、眼睑、瞳孔、嘴唇、脸颊与手部。
- 3D 故事节拍按需交替镜头尺寸：表情节拍用特写/大特写，空间动作用较宽镜头，仅在不平衡、追逐、惊喜或喜剧恐慌时使用斜角镜头；不因"风格是 3D"就重复相同比例。3D 角色说话时在发声秒数描述张嘴/闭嘴。
- 带音乐的 3D 动画（除非用户要求静音或特定音频结构）：一个连续情感配乐匹配实际情感弧线、喜剧节拍、追逐节奏、对话时机与结局基调，并在对话、声音反应和重要音效下降低音量。

纸艺 / 纸定格动画 / 触觉解说：
- 纸张行为具有机械性与层次感，不是静态纸张纹理：背景与前景层可用视差、纸门、滑轨、翻页、拉片、折叠、铰链、工字钉、接头、插片、槽口、旋转圆盘与可见层厚度，当这些机制能阐明想法时。
- 场景像微缩物理舞台：前/中/背/远背层，复杂纸艺镜头暗示约 4-7 个可读层，有真实纸张阴影、无光泽纤维、接缝、褶皱、切割/撕裂边缘与分离平面。
- 镜头与过渡像拍摄小型纸制立体模型：缓慢推进、柔和横向视差、微距细节、轻微俯拍、穿越图层运动、翻页、纸张标签从镜头前扫过、纸门打开、圆形纸遮罩、纸屑、胶带/贴纸揭示或分层分离；除非明确要求，避免高速飞行镜头、霓虹光故障、玻璃破碎、金属擦除、科幻粒子、平滑 CG 变形和塑料表面。
- 声音来自可见纸张动作：纸张沙沙、翻页、卡片滑动、纸门、纸轨、铰链/工字钉咔嗒、拉片、胶带剥离、纸盒、轻柔爆裂与摩擦声；支撑触觉运动而不过度卡通化。

拼贴 / 剪贴簿 / 剪影 / 半色调拼贴 / 纸层：
- 触觉运动编排：元素出现、轻微回弹、压平在表面、暂停并锁定到位；运动像被物理放置，不是液体或矢量式的平滑变形。
- 受控纸艺语言：干净色块、黑白半色调照片剪影、选择性彩色卡纸、暖白色关键线、柔和物理纸张阴影、细微纤维、撕裂/切割边缘与分层接缝；除非用户要求，避免不匹配的牛皮纸、泛黄或脏污纸张、随机可读文本、虚假 UI、标志、水印和过棕的调色板。
- 仅当用户请求该构建结构、授权扩写或参考材料已暗示时采用"从干净色块开始 → 按可读顺序组装前/中/背景组 → 短暂锁定定格"的组装序列；纯转换模式保留提供的拼贴构图。
- 音频默认触觉拼贴拟音（纸张滑动、弹入、压平轻敲、沙沙、小卡扣、摩擦）；除非明确要求或提供的音频需要，不加 BGM、画外音、对话或字幕；被请求的 BGM/旁白保持纸张拟音为物理声音层，音乐位于纸张运动与旁白之下。

手绘实拍融合：
- 绘制实体出现时指定一致笔触语言（蜡笔、粉笔、彩色铅笔、粉彩、粗画笔、墨水或记号笔），包含轻微线条抖动、不均匀填充、模糊边缘、粗糙光晕（被请求时）与逐帧重绘感，同时实体在空间中可追踪且连续。
- 保持接地接触连续性：跟踪手持相机或移动主体时，绘制实体保持合理接触、遮挡、比例、阴影/表面附着与可读的追逐/跟随延迟；避免恐怖惊吓取景、抛光 CG 替代、均匀矢量线、平滑霓虹、毛绒玩具行为和断开的浮动涂鸦（除非明确要求）。
- 仅当用户请求该风格或授权扩写时在一个真实空间或相邻连续区域中展开，并可加入早期手/物体接触、通过先前形态痕迹的连续变换、可读运动路线与表面变换结局；纯转换模式不添加这些。
- 被请求的 15 秒手绘实拍融合默认五段时序（除非用户故事另有说明）：00:00-00:03 建立真实接触 → 00:03-00:06 开始逃脱或变换路线 → 00:06-00:10 以新接触或发现升级 → 00:10-00:13 准备空间变换 → 00:13-00:15 房间规模表面变换收尾，带柔和情感或俏皮节拍。

教育 / 解说 / 观点 / 抽象主题：
- 围绕一个核心学习目标或观点组织；每个主题、视觉隐喻、镜头节拍、文本事件与声音提示都帮助观众理解或记住该要点。

- 六节按序完整；独立文本输出以 `subject_definitions:` 开头、以 `non_diegetic_music:` 内容结束，插件输出按本次 JSON 契约填写六章节正文。

- 专门设计触发器只在被触发的类别中使用，未注入无关提示词；时间线有有意义的节奏高峰与关键信息的稳定制动时刻；未经用户请求没有额外字幕、标志、角色、产品、声明、分镜图稿、面板或水印；音频复用/参考关系在 `summary`、`retention_analysis`、镜头与两个音频章节之间不互相矛盾。

## MiniMax H3 知识库 — 翻译规范与术语表

> 本文件是整个知识库的翻译基准。所有文档（总览、技能说明、提示词写作指南、参考文档）的中文译文均遵循本规范，保证全库术语一致。

### 一、总体原则

1. **中文为主 + 术语保留**：正文译为中文；专业视频/影视术语首次出现或易歧义处标注英文原文，如「推镜头 (Push In)」「挤压与拉伸 (Squash and Stretch)」。
2. **功能性标识一律保留英文原文**，因为它们会被直接用作模型指令、字段名或文件定位：
   - 文件名、路径、模版占位符（如 `references/base-en.txt`、`{visual_style}`、`{player1_name}`）
   - H3 提示词字段名：`integrated_multimodal_description`、`overall_soundscape`、`non_diegetic_music`、`subject_definitions`、`summary`、`retention_analysis`、`detailed_description`
   - 镜头与标签标记：`[Shot 1]`、`<Picture 1>`、`<Subject 1>`、`<Video 1>`、`<Audio 1>`、`<d>...</d>`、`<scenetrans>`、`<cutoff>`、`(S1)`、`(S2)`
   - 保留度关系标记（固定英文值）：`fully_preserved`、`partially_preserved`、`attribute_transfer`、`weak_reference`、`fully_copy`、`partially_copy`、`reference`
   - 任务类型前缀：`[reference generation]`、`[video editing + audio reuse]` 等
   - 时间标记格式：`0.00 seconds`、`00:03.500`、`S.SS-second mark`、`0–1s`
   - 提示词示例代码块：示例中的字段名、标签、关系标记、任务类型前缀、说话人ID、对白标记、镜头标记、时间戳、帧对齐句式、运镜术语等指令性标识保留英文；描述性正文用中文书写；对白、歌词、旁白与画面内可见文字保留其原始语言
3. **生成模式名保留英文缩写**：T2VA / I2VA / FL2VA / L2VA / Ref2VA，首次出现时给出中文解释，之后直接使用缩写。
4. **忠实原文**：不增删内容、不改写结构、不添加原文没有的解释。官方已有中文版的技能，知识库直接收录官方中文内容（收录为 `技能说明.md`），不另行重译。
5. **标点与排版**：中文正文使用中文标点；英文术语、数值、代码、提示词示例内部保持原样。

## 当前单段提交的最后核对

这些检查在当前一次生成内完成，不增加模型调用，也不代替上面的详细规范。

1. 根据真实任务，基础填写三章节，参考填写六章节；字段值是正文，外层使用请求要求的 JSON 和当前真实 ID。
2. 两种 H3 模式的视觉主体正文都必须包含 `[Shot 1]`。参考任务即使只有一个固定镜头，`detailed_description` 也不能只写风格和逐秒行而漏掉镜号；其后仅在真实切点写一次连续编号的 `[Shot N] At MM:SS.mmm`。
3. 每个给定时间区间独占真实一行，从零覆盖非整数段尾；不能因为保留了完整结构示例，就照搬示例中未展开逐秒行的排版。
4. 只有人物身份/服装参考的图片，放在对应 Subject 的来源里，不另立 Picture 内容单元；没有帧锚点不代表身份只被部分保留。身份特征完整保留且只是执行新动作时使用 `fully_preserved`，不能因为动作来自文本而降为 `partially_preserved`。保留度取决于定义职责是否保留，不取决于图片是否是首帧。
5. 固定特征、光源、材质、左右位置、物体开向、声音及音轨窗口逐句核对来源；无依据的内容不补写。不要把示例中的“实拍、电影感、自然光照”等词当作每个任务必填默认值。
6. 同句原话只写一个发声块，原文、语言和标点不动；既定女声/角色声线、对应语言的已定语速及声源落实在声音描述中。没有声音依据不编环境底噪，没有配乐或明确禁止配乐时写 `N/A`。
7. 每一条专门规则只约束已经触发的类别及已定稿内容，不重新规划故事、替换切点、虚构官方品牌或新增表演/音乐/文字。只提交唯一确定的最终表达，不能留下姿态或镜头备选。

## 当前秒级交付的正式排版示例

上面六个完整案例保留参考、表演和声音规则；正式提交还必须满足下面的逐行排版。此示例假定原稿已经指定了蓝色开衫、木门、抬手后停下、固定机位和衣物摩擦声，不能把这些内容当作别的段的默认设定。

正文排版：

```text
[Shot 1] 固定中景，小林穿蓝色开衫，站在木门前。
从 00:00.000 到 00:01.000，小林开始缓慢抬手，衣袖随动作移动，发出轻微衣物摩擦声。
从 00:01.000 到 00:02.000，小林继续抬手，手向门前位置移动，机位保持固定。
从 00:02.000 到 00:03.000，小林的手停在门前，保持这一原定结束状态，机位不变。
```

插件请求为参考六章节时，合法 JSON 示例：

```json
{"prompts":[{"segment_id":"仅示例ID_正式输出换为当前真实ID","subject_definitions":"<Subject 1> 是小林，蓝色开衫和身份特征来自 <Picture 1>；图片仅提供身份与服装来源，不作为帧锚点。","summary":"[reference generation] 展示 <Subject 1> 在木门前缓慢抬手后停下的过程，固定中景，无对白、无配乐。","retention_analysis":"<Subject 1>（出现在 [Shot 1]）: fully_preserved - 保留已定义身份及蓝色开衫，执行原定抬手动作。","detailed_description":"[Shot 1] 固定中景，<Subject 1> 小林穿蓝色开衫，站在木门前。\n从 00:00.000 到 00:01.000，小林开始缓慢抬手，衣袖随动作移动，发出轻微衣物摩擦声。\n从 00:01.000 到 00:02.000，小林继续抬手，手向门前位置移动，机位保持固定。\n从 00:02.000 到 00:03.000，小林的手停在门前，保持这一原定结束状态，机位不变。","overall_soundscape":"只保留原定抬手时的轻微衣物摩擦声，无对白及其他声源。","non_diegetic_music":"N/A"}]}
```
