# 视频规划师

**语言 / Language：** 🇨🇳 简体中文（当前） ｜ [🇬🇧 English](./README_EN.md)

一个 ComfyUI 插件，把一条长视频拆成若干小段分别生成，最后拼成完整视频。

生成能力全部来自 ComfyUI 官方的 MiniMax H3 节点，本插件负责「AI 规划 → 拆段 → 逐段跑 → 拼回去」的编排工作。AI 规划（LLM 生成分镜、逐段优化提示词）走进程外 HTTP 推理，不占显存。

## 能做什么

- **AI 一键分镜**：在 AI 规划页填一份 brief（主题、总时长、段数、平台、技能等 12 项），LLM 按短视频方法论直接产出多段分镜草稿，不用手工逐段填。
- **逐段 AI 提示词优化**：分镜先落成「剪辑时间轴」预演草稿，可裁剪/分割/删除/重排、可缩放细看，再让 LLM 按所选技能文档逐段优化画面提示词，满意后「填充节点」写回时间轴。
- **把长视频拆成多段**：在时间轴上添加若干段，每段写自己的提示词、设自己的时长。
- **每段挑一种生成方式**：文字生视频、图片生视频、首尾帧生视频、参考素材生视频、视频改视频、参考素材+视频改视频，一共 6 种，段与段之间可以混着用。
- **每段挂参考素材**：图片、视频、音频都行，可以用 `<Picture 1>` 这种标签在提示词里点名引用。
- **段之间可以平滑过渡**：打开「渐变过渡」开关后，上一段末尾的画面和声音会作为续拍条件带进下一段，接缝处不再叠两段画面，只给续拍段开头做轻微的色光衔接，接缝不突兀；关闭时每段独立生成、接缝硬切。
- **跑过的段自动存下来**：每跑完一段就存到硬盘。下次再跑，没改动的段直接读回来，不重新生成，几十秒就能出片。
- **段缓存看得见、管得住**：节点时间轴工具条上的「缓存」条可查统计（版本/条目/大小）、一键清空、「缓存失效版本 +1」整体作废重采样；换素材文件、改上游段内容都会自动级联失效重算，不会静默用旧结果。
- **节点上的时间轴也能缩放**：挂在节点里的时间轴面板同样支持 **1～40 倍**缩放（工具条右侧「适配全部 / 缩小 / 滑块 / 放大」＋实时倍率读数），段多或节点窄时可**滚轮缩放**、**拖时间标尺平移**或用横向滚动条浏览；纯视图操作，不改段时长、不写 widget、不影响段缓存签名。
- **只跑勾选的段**：每段下面有个「运行」开关，勾了才重新生成；没勾但之前存过的段照样会拼进最终视频。
- **过期回写一律拒绝**：加载计划、上传素材、AI 规划等异步操作期间如果你已换节点/删段/改草稿，结果只认发起时的目标，过期的回写会被拒绝并提示重试，不会写错地方。
- **跑前预检、跑中可预算**：生成前先校验素材、数值、每段时长与官方节点，问题明确报错；完成报告含「计划 → 对齐/裁剪后预计 → 输出播放」三时长与成片内存预算，可选硬限额在解码前中止，而不是跑一半才炸或 OOM。

## 怎么用

### 第一步：把节点连上

在工作流里添加节点 **长视频规划师**（node_id `长视频规划师`）。

它有 5 个输入口：

| 输入口 | 说明 | 是否必填 |
|---|---|---|
| `fl2va模型` | 文字/图片生视频用的模型 | 选填，用到才连 |
| `ref2va模型` | 参考素材生视频用的模型 | 选填，用到才连 |
| `CLIP编码器` | 文字编码器，必须是 minimax 类型（Qwen3-VL） | 必填 |
| `视频VAE` | 视频解码器 | 必填 |
| `音频VAE` | 音频解码器 | 必填 |

上面两个模型口，用哪种任务连哪种就够了；两个都用就都连上。

前五个输出仍是图像、音频、帧率、总帧数、报告文字，原保存和预览连线不变。第六个「初采产物」专供可选的「精修与放大」，不用二采时可以不接。

### 第二步：打开底部状态栏

插件加载后，ComfyUI **页面底部**会自动出现一条「长视频规划师」面板，标题栏里嵌着左右两个 Tab：**AI 规划**（左，默认）和**提示词编辑**（右），点 Tab 即切换页面（再点当前 Tab 收起面板、又点一下重新展开）。

**提示词编辑**页里面有：

- **生成类型**：切换 6 种任务
- **预设**：从下拉里选一个常用提示词片段，正文自动写回全局提示词（详 [预设](#预设)）
- **提示词编辑框**：写全局提示词，会加在每一段的前面
- **参考素材区**：上传或拖入图片/视频/音频，重复上传自动去重：同名同内容秒传复用；同名不同内容自动改名并存，不互相覆盖；拖入时按文件类型自动归到对应素材框（图像进图像、视频进视频、音频进音频），某类达到上限（图像 9、视频 3、音频 3）后不再增加、类型不认的当场拒收；三类素材各有固定三行高的素材框，装不下时在框内用滚轮滚动查看；全段共用开关下方有「清理素材」按钮，一键清空本段全部素材，弹窗确认后才生效，防误触
- **计划数据**：一键保存/加载整套工程配置（详 [计划数据](#计划数据保存加载工程)）
- **时间轴**：主要工作区

节点上对应的输入框会自动隐藏，所有数据都存在节点里，状态栏只是编辑器。

**AI 规划**页提供一键分镜、剪辑时间轴预演与逐段 AI 提示词优化，见 [第三步：AI 一键规划（可选）](#第三步ai-一键规划可选)。

### 第三步：AI 一键规划（可选）

不想手工逐段填，可以走这条链路（首次使用需先配好 API 模型，见 [API 模型配置](#api-模型配置)）：

1. **填 brief**：主题（必填）、总时长（分钟，默认 3）、每段建议时长（默认 5-8 秒，控制分镜节奏）、段数（0=自动分配）、默认任务、钩子、语言（H3 稳定支持的 11 种对白语言）、风格、平台、受众、技能、辅助，共 12 项。
2. **选模型、点「生成规划」**：后端调 LLM 产出分镜 JSON（首段强制「钩子」、末段须为「结尾/CTA」，每段 5–15 秒），写进节点里隐藏的「剪辑草稿」。草稿**不参与生成**，节点时间轴不受影响。若段数不足，后端会**自动重试一次定向补齐**（不会拿同一段画面充数）；仍不足时按**未完成草稿**返回并在面板橙色提醒。选了知识库技能时，面板会诚实回显**实际进入请求的来源/截断/缺失**计数。
3. **剪辑时间轴精调**：类剪辑轨道——点空白加段、拖段卡边缘改时长、「✂ 分割」在播放头处一分为二、「🗑 删除」ripple 删除（其余段自动闭拢）、多选、拖拽重排；轨道上方的时间标尺始终显示（草稿为空也照常排出 0～30 秒刻度），并随总时长自动调节密度（秒级到小时级）。段卡直接显示 序号/区间/标题/职能/字幕/关键词。
4. **缩放细看（纯视图）**：工具条上的「适配全部 / 缩小 / 滑块 / 放大」把时间轴拉到 **1～40 倍**，旁边实时显示当前倍率；也可以在轨道上**滚轮缩放**（Ctrl+滚轮／触控板捏合更灵敏）、**拖时间标尺横向平移**、或用底部横向滚动条。放大时刻度自动递进（小时 → 分 → 秒 → 0.1s），几十分钟的片子也能逐段精确对位。缩放只改视图宽度：不动任何段的起止时长，不写草稿、不影响节点时间轴与段缓存，裁剪/分割/预览定位/重排在任意倍率下坐标照样准确。
5. **「✨ AI生成提示词」**：按 brief 与技能文档让 LLM 逐段重写完整画面提示词，按启用状态自动分流——**全部启用**时整批生成，只覆盖「启用」的段（工具条「启用/全部启用/全不启用」管理）；**部分启用**时把全部段作为**只读上下文**一起上传、服务端**仅改写启用段**（未启用段保持原 prompt，也不用凑段数），哪段上传就自动回填哪段。生成用的 技能/辅助/模型 在轨道上方生成行。逐段回写按段身份映射，**某段失败保留原草稿并标明**（不会把旧词当新结果静默盖掉），失败段会弹确认。
6. **单段精修**：点段卡选中后，右列可编辑 标题/结构/字幕/提示词 四个字段，与段卡对应板块双向同步（「结构」为 UI 标签，即段卡上显示的叙事职能字段）。
7. **「⬆ 填充节点」**：满意后一键把「启用」范围内的草稿段写进节点的 `时间轴数据`（覆盖需确认；非全启用时仅填充启用段并把时间无缝收紧，禁用段留在草稿里，全部启用时效果与以前一致）。之后按普通时间轴一样生成。

> LLM 调用走进程外 HTTP（云端/本地同一套代码），**不占显存**、不动采样执行链。规划失败会明确报错，不会伪造演示内容。

### 第四步：编辑时间轴

- **加一段**：点轨道空白处，或者点「+」按钮
- **改时长**：拖段卡的左右边缘，或者用段卡下方的时间输入框
- **勾/不勾运行**：段卡下方那个开关。勾了才重新生成；不勾但之前存过就直接用旧的
- **改提示词、挂参考素材**：点段卡进去编辑
- **播放头**：拖动可以看到某个时间点在哪一段
- **渐变过渡**：时间轴工具条上的开关，打开后段与段之间会平滑衔接（尾帧上下文锚定 + 续拍段开头色光衔接，接缝零重叠）；关闭时硬切

时间轴数据以 JSON 形式存在节点的 `时间轴数据` 输入框里，可以复制粘贴，方便存档和分享。

### 第五步：点 Queue Prompt 开始生成

生成过程分两步：

1. **先一段一段跑采样**，每段跑完立刻存到硬盘（每段大约 45 MB）
2. **全部段都跑完后再统一解码、拼接**成最终视频

这么拆是为了让显卡在解码时能空出来，不然 16GB 显卡跑高分辨率长段时会慢十几倍。

底部状态栏会显示「生成中 3/7」这样的段级进度。

## 独立精修与放大（可选）

把主节点第六口「初采产物」接到 **精修与放大**，再把二采结果接到保存节点；原初采保存分支可保留。模型、CLIP 和 VAE 在新节点上独立接线，初采产物不携带模型。

- **先精修全部段，再放大**：默认精修强度 0.20；设为 0 跳过精修。不会把整片初采图像重新编码，也没有放大后的第三次采样。
- **三种放大方式**：Lanczos、像素模型、H3潜空间；倍率 1–4，目标尺寸按 32 对齐，实际尺寸见报告。像素模型需连接对应模型；H3方式需自行准备兼容权重——从 <https://huggingface.co/LBH-123-AI/Minimax_h3_latent_Upscaler> 取 `.safetensors` 放进 `ComfyUI/models/latent_upscale_models/`（和下面「渐进分辨率采样」用的是同一份权重），插件不自动下载，同目录里的 `.pth` 也不会出现在下拉框。
- **声音与时长保持**：直接复用初采最终音轨、帧率和总帧数，不重解码或变速；不回写初采段与素材。精修节点有独立整体进度，原段级进度保留。
- **独立缓存**：精修和 H3 放大缓存与原初采缓存分开；原「清空段缓存」按钮不清它们。替换权重后可增加新节点的「缓存失效版本」。

### 默认：内存直连

`长视频规划师 → 精修与放大 → 保存`

不插入交接节点时，仍在同一个宿主任务里传递内存包，不增加交接文件、不拆任务、不请求全局深清理；初采完整图像可能仍由宿主持有。

### 可选：插入「初采交接与清理」

`长视频规划师 → 初采交接与清理 → 精修与放大 → 保存`

仅有效输出链中包含该节点时，提交前才弹窗确认并启用三阶段：**A 初采及保存、分段落盘 → C 请求全局清理 → B 门控通过后逐段二采及保存**。无需手动添加内部读取节点；悬空交接节点不触发分阶段。

- 仅在专用空闲队列中使用，不要同时从其他窗口或 API 提交任务。清理会影响宿主模型和节点内存缓存，但不删除已保存视频、交接文件或磁盘缓存。
- A 整图失败不启动 C/B；`C_REQUESTED` 仅表示已申请，不能当作清理完成。B 门控通过后才展开二采模型加载及业务图。
- 交接节点提供状态、「取消交接」和「仅重跑二采」；重试必须仍持有本次任务的控制能力，使用当前图参数，重新执行 C/B，可能重复保存。页面重载后不自动恢复控制，也不自动寻找最近产物。
- 目前只接受单条明确的交接链，不支持批量、局部执行、跨阶段拉线或未知共享副作用节点；普通 `/prompt` 不会自动拆图，API 使用者需走专用交接接口。

**验收边界：** 已有 CPU 契约、隔离宿主执行器和前端运行时测试；真实浏览器交互、GPU画质/峰值、真实全局卸载及实际保存插件组合仍未验收。分段读取也不能消除最终完整 IMAGE 的内存下限，预算不包含全部模型和未知激活，不保证不 OOM。

## 渐进分辨率采样（可选）

每段先把前几步去噪跑在更小的画布上，抬升到目标分辨率后再跑完剩下的步。**总去噪步数不变**，省下来的是前几步的计算量。不连线时一切照旧。

**怎么连**：新建「SelfLift配置」节点，把它的「配置」口连到主节点最下方那个「SelfLift配置」口。不连＝单阶段采样，段缓存也不受影响。

- **低清缩放**（0.25–0.95，默认 0.5）：低清画布 = 目标画布 × 本值，再对齐到 32 的倍数。0.5 时低清那几步的视频 token 大约只有四分之一。
- **高清步数**（默认 6）：按目标分辨率跑的步数；低清步数 = 主节点「步数」− 本值，两段各至少 1 步。
- **采样器必须选 euler**：选了别的会在开跑前报错并点名是哪个参数不对，不会悄悄按普通采样跑。
- **抬升画质靠 H3 潜空间放大权重**：从 <https://huggingface.co/LBH-123-AI/Minimax_h3_latent_Upscaler> 下载（作者 LBH-123-AI，Apache-2.0；取 `minimax_h3_latent_upscaler_3d_conv_v1/` 里的 `fp16.safetensors` 或 `bf16.safetensors`，各约 691 MB），放进 `ComfyUI/models/latent_upscale_models/`，插件不会自动下载。⚠️ 本插件只列 `.safetensors`，同目录里的 `.pth` 不会出现在下拉框。
- **不选权重就得勾选「允许插值降级」**：改用双线性直接抬升。参考实现作者的同种子自测里，这一档**会出现可见伪影**（不只是变糊），只适合先看构图和运动，不适合当成正式成片。
- **时长、帧数、声音都不受影响**：帧数只由时间轴跨度和 24fps 基座决定，跟分辨率无关；抬升只改画面的空间尺寸。
- **缓存怎么算**：换上这版不会让已有段缓存整体作废。但连上配置后，「低清缩放 / 高清步数 / 放大权重」任一项一改，全部段都要重跑——这几项写在每段的缓存指纹里。
- **参数不合法一律开跑前报错**：步数小于 2、高清步数越界、缩放超出区间、取整后等于没降分辨率、既没选权重又没勾降级——都会点名是哪个参数，不做静默回退。

**值不值这么跑**：设上环境变量 `H3_计时=1`，同素材同种子跑两遍对比——一遍断开配置（全高清 + euler），一遍连上配置，看日志里「段N 采样计时」的合计；连上配置时还会多一行「段N 渐进采样细分」拆出低清采样、抬升、高清采样各花多久。⚠️ 提速倍数、抬升后的画质、峰值显存目前都没有显卡实测数据。

## API 模型配置

AI 规划功能需要一个 OpenAI 兼容的 LLM（云端/本地同一套代码，推理在进程外完成，不占显存）。

在 **ComfyUI 设置 → 🎬 长视频规划师 → API 模型配置** 里设置：

- **预设模型**：内置 Kimi-K3（列表首行，默认），在该行填上 API Key 即可用
- **自定义模型**：可添加多条（名称 / Base URL / 模型名 / API Key），单选钮选定当前模型。云端如任意 OpenAI 兼容端点（Moonshot、DeepSeek 等），本地如 Ollama / LM Studio（开 `/v1` 兼容）
- **按模型 API Key**：每个模型各自保存密钥，判据是保存时输入框为空或含 `****` 即沿用该模型旧 Key。密钥沿用绑定规范化端点（协议+主机+端口+有效路径）：改了地址视为新端点，必须重新填 Key，旧凭据绝不会发往新址；请求也不会随重定向把 Key 带到别的地址
- **测试连通性**：每行 Key 输入旁的按钮，发一次最小请求验证 名称/地址/Key，行内显示 ✓/✗，不必先保存
- **全局请求超时**：120–3600 秒，默认 120。思考模型（Kimi-K3 等）配合技能文档长注入耗时偏长，建议 300–600

配置存在 `规划/规划器配置.json`（已进 `.gitignore`，明文 Key 不入库）。

## 计划数据（保存/加载工程）

提示词编辑框上方工具行的**最右**，有「计划数据」下拉（加载）+ 「保存」按钮。用来把当前节点的全套配置存成 JSON 文件，下次一键复用。

### 保存的是什么

一份计划包含：

- 全部普通 widget：任务类型、输出分辨率、百万像素、帧率、步数、采样器、调度器（「缓存失效版本」是运行时作废手段，**不随计划保存**）
- 全部隐藏 widget：全局提示词（预设正文写入）、参考共用、尾帧锚定、运行选择
- 完整时间轴 JSON（每段的 task/prompt/start/end/run/refs）
- 参考素材清单（图片/音频/视频文件名）
- 剪辑草稿（AI 规划页的预演草稿，含 brief 表单正文，随计划一并保存/恢复；加载时计划无草稿则清空节点上的不相干旧草稿）

存储位置：`插件根/计划数据/<名>.json`。目录由后端按需创建，无需手动建。

### 保存步骤

1. 点「保存」按钮
2. 输入计划名（不含 `.json` 扩展名）
3. 同名计划会二次确认覆盖；覆盖时保留原「创建时间」字段

### 加载步骤

1. 从「（加载）」下拉里选一条
2. 当前节点已有时间轴数据（段数 > 0）时会二次确认覆盖
3. 加载完成后所有 UI 自动同步（时间轴重建、提示词回填、参考素材列表刷新）
4. 加载后下拉值清回「（加载）」占位，允许再次选同一条触发加载

### 命名规则

计划名会被前后端**双重校验**（前端预校验给用户即时反馈，后端仍会二次校验），规则：

- 不能为空、不能只是空白
- 不能含 `\ / : * ? " < > |` 或控制字符（含换行/制表符）
- 不能以点或空格开头/结尾（Windows 会静默剥离）
- 不能是 `.` / `..` / Windows 保留名（CON/PRN/AUX/NUL/COM1-9/LPT1-9）
- 长度 ≤ 100 字符

### 参考素材缺失处理

加载时后端会对照媒体池（`ComfyUI/input/`）检查：

- 计划里引用的图片/视频/音频文件已被删掉 → **保留原引用不剔除**，只登记为「缺失素材」（refs 的位置就是 `<Picture N>` 标签，静默过滤会让其余素材悄悄前移造成错指）
- 前端 toast 提示「跳过 N 个缺失的参考素材：xxx、yyy」，加载不会中断
- 真正的拦截在采样前：执行预检会点名阻止引用缺失素材的可运行段，其余段不受影响

这样即便计划指向的素材已经不在，也能立刻看到诊断，而不是等到点 Queue Prompt 跑到一半才炸。

### 典型用途

- 把常用工程配置（如「9:16 竖屏 + 20 步 + 电影风格 + 特定分镜模板」）存成一条计划，下次一键复用
- 团队之间分享完整的生成方案（配合 `预设/` 里的提示词模板）
- 存档重要的时间轴（比直接复制节点 JSON 更完整，因为包含所有隐藏 widget）

## 中途取消或报错怎么办

已经跑完的段**不会丢**，它们已经存到硬盘上了。

正在跑到一半的那段**会丢**，下次要重新跑。

如果你只想拿到已跑完的那些段：

1. 打开时间轴面板
2. 把没跑完的段、以及后面还没轮到的段的「运行」开关**全部关掉**
3. 只留下已经跑完的段的开关是勾上的（其实关掉也行，只要有缓存都会拼进去）
4. 再点一次 Queue Prompt

这次跑会全部命中缓存，几十秒就能出片。控制台报告里会写「段N: 命中缓存」，说明这一段是直接从硬盘读的。

## 注意事项

**缓存放在哪**

默认在 `%TEMP%/长视频规划师_段缓存/`。想改位置就设环境变量 `长视频规划师_段缓存_DIR`。

老版本的缓存目录会在插件启动时自动删掉，不用手动清理。

**分辨率怎么算**

由「输出分辨率」（选宽高比）和「百万像素」（选画面精细度）两个 widget 共同决定。默认 `0.4 百万像素 + 16:9` 出来是 **864×480**。

百万像素调得越大越吃显存，`4.0 + 21:9` 会到 3136×1344，量力而行。

**帧率是什么意思**

节点上的「帧率」输入框只是给输出视频文件打的标签，实际生成时用的**永远是每秒 24 帧**（官方模型的固定值）。想让视频慢放/快放，改帧率数字就行；想改真实运动速度，改段的时长。改帧率也**不影响段缓存**（自 h3-7 起它不参与缓存指纹）。

**段之间怎么衔接**

「渐变过渡」开关控制（默认关闭）：

- **关**（默认）：每段独立生成，接缝直接硬切，不做任何过渡处理
- **开**：上一段末尾 22 帧画面和约 1 秒尾音频作为「续拍条件」带进下一段（直接传 latent，不经解码再编码），下一段从上一段结尾自然接着拍；接缝零重叠硬切，只对续拍段开头做轻微的低频色光衔接（色调/亮度贴合上一段结尾，不做两段画面叠化）

如果出现花屏、幻影、鬼影，先把「渐变过渡」关掉试试，看是不是模型本身的问题。

⚠️ **切换这个开关会让所有段的缓存失效、全部重新采样**（上下文帧数是段缓存指纹的一部分，开关一变指纹就变）。已经跑好的段也会被重算，不是只对接缝重新拼一下。切换前请预留完整生成时间。

**换了 checkpoint 之后**

想让所有段重新按新模型跑一遍，不必手动删缓存目录：改节点上的「缓存失效版本」widget（或在节点时间轴工具条的「缓存」条点「+1」/直接填数后回车）即可整体作废旧段重采样；也可点该条「清空段缓存」直接删除磁盘缓存产物（不可撤销，仅影响本机，不碰其它文件）。

**只连了一个模型口能跑吗**

能。插件只会检查你**当前时间轴用到的任务**对应的模型有没有连，没连的话会明确报出来「哪个任务缺哪个模型」，其他情况都不管。

**某一段没有音频会补静音对齐**

如果某一段没有音频而其他段有（比如中途才连上音频 VAE），拼接时不再「跳过缺的那段」——而是按该段裁后帧数补一段等长静音，保证音轨总长与视频帧时间轴严格对齐，不会音画不同步。报告里会多一行信息提示「N/M 段无音频，已按等长静音补齐对齐 A/V」；若全部段都没音频，则输出为无声成片。

**长视频的成片内存边界**

成片节点输出是整段 IMAGE，拼接时全片必须留在内存里（这是节点接口决定的硬边界）。参考：180 秒、768×1344 的 float32 成片约 50 GiB。所以「内存」建议 32GB 起步只适用于短片；生成前的「内存预算」报告行会按你的规模先估一把，也可用 `H3_内存硬限额_GiB` 在超限时于解码前明确中止，而不是等 OOM。

**诊断计时（默认关闭）**

设环境变量 `H3_计时=1` 后，日志按段输出采样四步（参考解码/条件组装/段间连续/采样器）、缓存读写 IO、解码与拼接耗时及内存峰值，用于定位「慢在哪」。默认关闭、纯观测，不改变任何产物与行为。

### 宿主与官方节点

- **[Comfy-Org / ComfyUI](https://github.com/Comfy-Org/ComfyUI)**：本插件的宿主环境。整个「规划 → 拆段 → 逐段跑 → 拼回」编排都构建在 ComfyUI 的 V3 节点 API、执行器与缓存机制之上；前端面板、设置页、主题变量亦全部复用 ComfyUI 前端框架。

- **[MiniMax H3](https://github.com/MiniMax-AI/MiniMax-H3)（稀宇科技 MiniMax）**：多段视频/音频生成的核心基座模型，本插件的 6 种任务与 24fps 时间基座都来自它。
